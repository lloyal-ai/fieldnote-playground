Continuous Tree Batching: A Measurement Note

Field note · September 2026 · Fixture for the documents ability

Abstract

We measure how the cost of a multi-agent research run scales when every agent shares one attention context. In continuous tree batching, branches are sequence ids over one shared context and a decode step advances every live branch at once, so the cost of a run is set by how full the cache is, not by how many branches exist. We report cells consumed and wall-clock seconds for four fan-out configurations on a 4-billion-parameter model.

Method

Each configuration runs the same research question with a different fan-out width. The baseline runs one agent. The wide configuration runs four agents in parallel from a shared spine. The deep configuration chains four agents so each inherits the previous agent's context. The full configuration runs four parallel agents each of which delegates once. Cells are counted as key-value cache entries at the moment the pool closes; seconds are measured from the first token of the plan to the last token of the brief.

All runs use the same prompt, the same reranker, and the same eight-token stall budget. The reranker scores passages against the original question so that a retrieval two hops away stays on topic. No run was repeated; the numbers are single observations.

Results

Table 1 lists the cells consumed and the seconds elapsed for each configuration. Cells grow with width because every parallel agent holds its own suffix; seconds grow more slowly because the parallel branches decode in one batched step.

The deep configuration costs more cells than the wide one at the same agent count because each chained agent carries its predecessor's context forward. The full configuration is the most expensive in both measures but still finishes in under three times the baseline's seconds while doing eight agents' worth of work.

Discussion

Two observations follow. First, the fan-out width, not the agent count, is what sets the cell cost: the wide and deep runs have the same number of agents and differ by almost eight hundred cells. Second, wall-clock time tracks the number of batched decode steps rather than the number of agents, which is why the full configuration is cheap in seconds relative to its cells.

The obvious limitation is that these are single observations on one question and one model. A second limitation is that the stall budget was fixed; a wider budget would let the deep chain recover from a poor early retrieval and would likely raise its cell count further.

Conclusion

Sharing one context across a research pool makes the cost of a run a property of cache fullness. Width is the lever, depth is the tax, and batching is why the wall clock forgives both.
